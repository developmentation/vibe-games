# Requirements — Continuous Improvement

- Retrospective section describes the what-went-well, what-could-be-better, and action-items format
- Page states retrospective notes and action items must be stored in the project wiki or Confluence space
- Quality metrics table lists four key indicators: defect density, test coverage, deployment frequency, and mean time to recovery with targets
- Page states teams significantly outside metric targets will be engaged by the TI Quality team
- Technical debt section states at least 20 percent of sprint capacity must be reserved for debt reduction
- Technical debt callout states debt creating security risk must be treated with the same urgency as a security finding
- Post-incident review section states blameless post-mortems must be completed within five business days of a production incident
- Post-mortem structure list includes timeline, root cause, what worked well, what could be faster, and action items
- Capability maturity self-assessment table lists practices across foundational, managed, advanced, and optimizing levels
- Sidebar navigation lists all program pages with correct active state on Continuous improvement
