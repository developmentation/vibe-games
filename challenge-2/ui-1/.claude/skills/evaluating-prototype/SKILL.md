# Evaluating a prototype

Cross-walks requirements → artifacts and runs 34 structural / accessibility / design-system / JS-hygiene checks. The skill is conservative: any FAIL blocks completion until either the prototype or the requirements are updated.

## Inputs

- `apps/<slug>/index.html` (must exist — generated by `generating-alberta-page`'s build.mjs)
- `apps/<slug>/requirements.md` if present — bulleted list, drives the crosswalk
- `apps/_shared/vendor/css/goa-{base,layouts,components}{,.print}.css` must exist on disk

## Workflow

```
- [ ] 1. node .claude/skills/evaluating-prototype/scripts/evaluate.mjs <slug>
- [ ] 2. Read apps/<slug>/evaluation.md
- [ ] 3. For each FAIL, fix the prototype OR document the deviation
- [ ] 4. Re-run until every check is PASS or WAIVED-with-reason
```

## What the evaluator checks (34 checks)

**Structure** — semantic landmarks per the canonical template
- `<!DOCTYPE html>`, `<html lang="en">`, viewport meta
- Single `<h1>`, heading order never skips
- `<main id="main" role="main">`
- `goa-skiplinks` block before the header
- `dialog-off-canvas-main-canvas` wrapper
- `goa-header`, `goa-breadcrumbs`, `goa-page-header`, `goa-footer` blocks present
- `goa-logo` with the SVG wordmark

**Design-system fidelity** — vendored CSS used correctly
- All 6 split stylesheets (`/_shared/vendor/css/goa-{base,layouts,components}{,.print}.css`) imported
- No live alberta.ca CSS bundle URLs
- No legacy monolithic `/_shared/vendor/alberta.css`
- Forms use `.goa-form` / `.goa-field`
- Buttons use `.goa-button`
- No legacy `.form-item` / `.form-required` / `.form-text` classes
- No utility-CSS framework (Tailwind / Bootstrap / Bulma / Foundation)
- All 6 vendored CSS files exist on disk

**JS hygiene** — nothing that crashes the page
- No `goa.init`, `ab.init`, `abComponents.init` orphan calls
- No Google Tag Manager scripts
- No Drupal-settings JSON blob
- At most one `<script src="./app.js">` tag

**Accessibility heuristics**
- Every `<img>` has alt
- Every form control has a `<label>`
- Live region for form errors
- noscript fallback present

**Responsiveness**
- viewport sets initial-scale=1

**Requirements crosswalk**
- For each line in `requirements.md`, the evaluator tokens-matches against the rendered HTML

## Severity

- **FAIL** — blocks sign-off; ship-stopper
- **WARN** — should fix; may waive with a written reason next to the offending element
- **PASS** — no action

## Requirements.md shape

Bulleted list. The crosswalker greps each line's tokens (4+ chars) against the rendered HTML. Half or more must match for a PASS.

```markdown
- User can submit a description of the red tape they encountered
- Form requires a regulation/policy reference
- Submission persists to an audit trail
- Page has a public help link to the Red Tape Reduction Office
```

## Multi-page programs

Run the evaluator on every page of the program. All pages must report **0 FAILs** before sign-off. The structural and JS-hygiene checks catch the most common cross-page consistency bugs (e.g. forgetting a viewport tag on one page).
